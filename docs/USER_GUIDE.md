# MySQL Backup Utility — инструкция по эксплуатации

Версия: MVP 0.1.0 · ОС: Windows 10/11 (64-bit)

## 1. Назначение

Программа создаёт резервные копии баз данных MySQL/MariaDB (через `mysqldump`, сжатие gzip),
восстанавливает их (через `mysql`), выполняет бэкапы по расписанию и удаляет старые копии (ротация).

## 2. Что нужно до начала работы

1. **Утилиты mysqldump/mysql**: вкладка «Настройки» → **«Авто-поиск»**
   (ищет в Program Files — MariaDB/MySQL, XAMPP — и в PATH) → **«Сохранить пути»**.
   Если авто-поиск не нашёл — вписать полные пути вручную (кнопки `...`), например
   `C:\Program Files\MariaDB 12.2\bin\mysqldump.exe`, и сохранить.
   Проверка вручную: `where mysqldump; where mysql` в PowerShell.
   Без найденных утилит задачи завершаются понятной ошибкой в «Логах»,
   а не «Не удается найти указанный файл».
2. Доступ к серверу MySQL: хост, порт (обычно 3306), логин, пароль, права минимум
   `SELECT`, `SHOW VIEW`, `TRIGGER`, `LOCK TABLES` (для восстановления — полные права на целевую БД).
3. Место на диске для архивов.

Файл запуска: `MySqlBackupUtility.exe` (self-contained, .NET 8 — отдельная установка runtime не требуется).

### 2.1. Установка через MSI

Поставляются два установочных пакета (файлы `dist\...msi`):

| Пакет | Куда устанавливается | Права |
|-------|----------------------|-------|
| `MySqlBackupUtility-0.1.0-win-x64.msi` | `C:\Program Files\MySqlBackupUtility` (все пользователи) | **требуются права администратора** |
| `MySqlBackupUtility-0.1.0-win-x64-peruser.msi` | `%LOCALAPPDATA%\Programs\MySqlBackupUtility` (только текущий пользователь) | **не требуются** |

Порядок установки:
1. Откройте папку с `.msi`.
2. Для пакета «для всех пользователей»: правый клик по файлу → **«Запуск от имени администратора»**,
   в запросе UAC нажмите **«Да»**. Если прав администратора нет — используйте пакет
   `...-peruser.msi` (обычный двойной клик, UAC не запрашивается).
3. По завершении на Рабочем столе и в меню «Пуск» появятся ярлыки **MySQL Backup Utility**,
   и программа запустится автоматически. Если окно не появилось — откройте её из меню «Пуск».
   При ошибке запуска выводится окно с текстом ошибки; подробности пишутся в
   `%AppData%\MySqlBackupUtility\logs\crash-*.log`.

> Если установка MSI невозможна (нет прав, блокирует антивирус), используйте портативный
> вариант `MySqlBackupUtility-0.1.0-win-x64-portable.zip`: распакуйте его в любую папку
> (например, `C:\Tools\MySqlBackupUtility`) и запустите `MySqlBackupUtility.exe`. Установка не нужна.

Удаление: **Параметры → Приложения → Установленные приложения** → *MySQL Backup Utility* → **Удалить**
(для варианта «для всех пользователей» потребуются права администратора).

Настройки и журнал хранятся в `%AppData%\MySqlBackupUtility\` (`app.db`, `logs\`, `default_folder.txt`).
Файловый лог: `%AppData%\MySqlBackupUtility\logs\app-ГГГГММДД.log`.

## 3. Первое подключение

1. Вкладка **«Подключения»** → **«Новое»**.
2. Заполнить: **Имя** (любое, например «Локальный»), **Хост**, **Порт**, **Пользователь**, **Пароль**.
   Галочка **SSL/TLS** — только если сервер требует шифрованное соединение.
3. **«Проверить соединение»** — должно появиться `OK. Сервер: ...` и зелёный индикатор внизу.
   При ошибке текст ошибки показывается там же, статус — красный.
4. **«Обновить список БД»** — программа запросит у сервера перечень баз (`SHOW DATABASES`)
   и покажет их с галочками. Системные (`information_schema`, `performance_schema`, `sys`) скрыты.
5. Отметить нужные базы (**«Выбрать все»** = все базы, включая те, что появятся позже).
   Выбор отображается в поле «Базы для бэкапа»: `*` — все, иначе имена через запятую.
6. **«Сохранить»**. Подключение появится в списке слева.

Замечания:
- Список баз относится к конкретному серверу: при переключении подключений он очищается,
  обновите его кнопкой.
- Подчеркивания в именах (`lora_gate`) отображаются корректно.
- Пароль хранится только в шифрованном виде (DPAPI), в открытом виде его нет нигде.

## 4. Первый бэкап вручную

1. Вкладка **«Главная»** → **«Новая задача»**.
2. **Подключение** — выбрать сохранённый сервер.
3. **База данных** — можно оставить пустым: подставится выбор из подключения.
   Либо вписать вручную: одно имя (`lora_gate`), несколько через запятую (`shop,blog`),
   `*` — все пользовательские базы сервера.
4. **Папка** — куда класть архивы (по умолчанию `Документы\MySqlBackups`, кнопка `...`).
5. **Периодичность** — выбрать обязательно (Daily/Weekly/Monthly/Interval), иначе пункт пуст.
6. **«Сохранить задачу»** — задача появится в таблице.
7. Выделить задачу → **«Создать бэкап сейчас»**.
8. Имя файла: `[ИмяБД]_[ГГГГММДД]_[ЧЧММСС].sql.gz`, например `lora_gate_20261014_091500.sql.gz`.
   Результат виден во вкладке **«Архивы»**, ошибки — во вкладке **«Логи»**.

## 5. Настройка расписания

Поля задачи:
- **Время (ЧЧ:ММ)** — для Daily/Weekly/Monthly, например `03:00`.
- **Daily** — каждый день в указанное время.
- **Weekly** — дни недели цифрами через запятую: 0=воскресенье, 1=понедельник … 6=суббота.
  Пример `1,2,3,4,5`: будни в указанное время.
- **Monthly** — **Число месяца** (1–28) в указанное время.
- **Interval** — каждые N минут (**Интервал (мин)**, минимум 5).
- **Хранить копий / дней** — ротация: `7 / 7` = держать не больше 7 последних копий
  и не старше 7 дней. `0` — без ограничения.
- **Включена** — выключенная задача планировщиком пропускается.
- Чекбокс **«Планировщик вкл»** в тулбаре (и пункт «Поставить на паузу» в трее)
  глобально разрешает/запрещает автозапуск.

Колонки «Статус» (OK/ERROR) и «След. запуск» показывают состояние. Точный следующий запуск
пересчитывается после каждого выполнения.

Важно: планировщик **встроенный** — работает, пока программа запущена, включая свёрнутое
состояние в трее. Если нужно выполнение без входа пользователя в Windows — создайте задачу
в системном «Планировщике заданий» (`taskschd.msc`), запускающую `MySqlBackupUtility.exe`.

## 6. Восстановление

- Вкладка **«Архивы»** → выделить архив → **«Восстановить...»**.
  Целевая БД: если задача была на одну базу — она подставится; если на несколько/все —
  программа спросит имя (по умолчанию первая из списка).
- Подтвердить предупреждение: **данные в целевой БД будут перезаписаны**.
- **«Восстановить из файла...»** — любой `.sql`, `.sql.gz` или `.zip` с дампом
  (используется первое подключение из списка; целевую БД ввести вручную).
- Ход операции — текстовые сообщения и прогресс-бар в строке статуса внизу окна.
- **«Удалить»** — удаляет файл и запись; **«Открыть папку»** — проводник с архивами.

## 7. Логи и диагностика

Вкладка **«Логи»** → **«Обновить»**: время, уровень (INFO/OK/ERROR), задача, сообщение,
размер и длительность операции. Зелёный/красный индикатор в строке статуса дублирует
итог последней операции. Дублирующий файловый лог — см. раздел 2.

## 8. Настройки

- **Папка бэкапов по умолчанию** — подставляется в новые задачи → «Сохранить».
- **Статус внешних утилит** — пути к `mysqldump`/`mysql` либо предупреждение, что их нет в PATH.
- **Сворачивать в трей** — при закрытии окна программа прячется в трей и продолжает работать.
  Полный выход: правый клик по значку в трее → «Выход». Контекстное меню трея:
  «Открыть», «Поставить на паузу» / «Продолжить», «Выход».
- **Автозапуск после перезагрузки/включения сервера** — кнопки
  «Включить автозапуск» / «Выключить автозапуск» в разделе «Настройки».
  При включении программа записывается в автозагрузку Windows
  (`HKCU\Software\Microsoft\Windows\CurrentVersion\Run`) и будет автоматически
  стартовать при входе в систему, после чего встроенный планировщик продолжит
  выполнение задач по расписанию. Строка статуса под кнопками показывает,
  включён ли автозапуск и по какому пути. Права администратора не требуются.

## 9. Типовые проблемы

| Симптом | Причина и решение |
|---|---|
| `mysqldump`/`mysql` не найдены (Настройки) | Нет MySQL Client в PATH — установить и добавить `bin` в PATH, перезапустить программу |
| `Unknown database 'xxx'` в Логах | Опечатка в имени БД; сверить со списком на вкладке «Подключения» |
| Список БД пуст после обновления | Нет прав `SHOW DATABASES` у пользователя либо нет пользовательских БД |
| Список задач/подключений пуст после сохранения | Нажать «Обновить»; проверить, что нажали «Сохранить» (не только ввели данные) |
| Программа «пропала» после закрытия окна | Она в трее (см. значок у часов) → правый клик → «Открыть» |
| После перезагрузки/включения сервера программа не запустилась | Настройки → «Включить автозапуск»; проверить статус под кнопками |
| MSI не устанавливается, ошибка **1925** / **1730** | Пакет «для всех пользователей» требует прав администратора. Клацните `.msi` правой кнопкой → «Запуск от имени администратора» и подтвердите UAC, либо поставьте пакет `...-peruser.msi` (права не нужны) |
| При удалении пакета ошибка 1925/1730 | Удаление варианта «для всех пользователей» тоже требует прав администратора: правый клик по «MySQL Backup Utility» в списке приложений → «Удалить» от имени администратора, либо `msiexec /x <код продукта>` в консоли администратора |
| Установка прошла, но окно программы не появилось | Откройте программу из меню «Пуск» (ярлык «MySQL Backup Utility»). Если не открывается — посмотрите `%AppData%\MySqlBackupUtility\logs\crash-*.log`; при пустом каталоге проверьте, не блокирует ли запуск антивирус/Защитник Windows (добавьте папку программы в исключения) |
| Программа не запускается, файл «исчезает» | Антивирус/Защитник Windows мог удалить `.exe` (неподписанный файл). Добавьте исключение и переустановите; либо используйте портативный `.zip`-вариант |
| `Access denied` при публикации новой версии | Старый `.exe` запущен — выйти через трей → «Выход», затем копировать/публиковать |
| Бэкап большой БД идёт долго | Норма: дамп + gzip потоковые, окно при этом не зависает; следить за строкой статуса |
| Ошибка доступа к сетевой папке | Запускать программу от пользователя с правами на эту папку; проверить путь |

## 10. Безопасность

- Пароли в `app.db` — только DPAPI-шифр текущего пользователя Windows; перенос файла
  настроек на другой ПК/пользователя сделает пароли нечитаемыми (придётся ввести заново).
- Пароль для `mysqldump`/`mysql` передаётся через переменную окружения `MYSQL_PWD`,
  а не через командную строку.
- Не давайте учётной записи для бэкапов лишних прав; для восстановления используйте
  отдельную задачу/подключение при необходимости.
